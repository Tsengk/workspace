# 使用说明 1

> 关联输出物模板：[输出物模板.md#7.2](../输出物模板.md)
> 目标：其他人可按说明完成运行和使用
> 对象：图像转换插件 `msgpack2ros4imageplugin3` 第二版（ap_tools 提交 `c19160f1`）

---

## 一、环境要求

| 项 | 要求 |
|----|------|
| 操作系统 | Ubuntu 18.04 / 20.04 |
| 依赖库 | libde265-dev（`sudo apt-get install libde265-dev`）、libturbojpeg、FFmpeg（libavcodec/libavutil/libswscale）、ROS（melodic 或 noetic）、rosbag、boost/tinyxml2 |
| 平台框架 | ap_tools 插件框架（`ap_tools_chain`）、icaos_tool 运行环境 |
| 目标产物 | `libmsgpack2rosimageplugin3.so`（插件共享库） |

## 二、构建方式

在插件目录 `ap_interface_use/plugins/msgpack2ros4imageplugin3/` 下执行：

```bash
# Ubuntu 20.04
./compile_2004.sh     # 生成 build_2004/libmsgpack2rosimageplugin3.so，并自动拷贝到 ap_tools_chain/runtime/x86_2004/bin

# Ubuntu 18.04
./compile_1804.sh     # 生成 build_1804/libmsgpack2rosimageplugin3.so，make install 到 ap_tools_chain/runtime/x86_1804/bin
```

> 说明：`compile_2004.sh` 会先对 `generator/ros_wks/` 执行 `catkin_make` 生成 ROS 消息依赖，再 `cmake .. && make`。

## 三、部署与配置

1. **部署插件**：将 `libmsgpack2rosimageplugin3.so` 放到运行目录 `/opt/usr/ap_adsfi/tools/ap_tools_chain/runtime/x86_2004/bin/`（确认与其它插件同级、有执行权限）。
2. **配置话题映射**：编辑运行目录下 `gsds_topic_config.tmp`，把要转换的图像话题指向本插件：
   ```
   <图像话题>,g2r,./libmsgpack2rosimageplugin3.so
   ```
   例：`compressed_image_list,g2r,./libmsgpack2rosimageplugin3.so`
3. **支持的输入**：话题消息类型 `MsgImageDataList`，其中：
   - `imageType=50`（JPEG）：原样透传发布，零解码零编码；
   - `imageType=53`（H265 裸流）：FFmpeg 软解码 BGR24 → TurboJPEG 编码 JPEG 发布；
   - 其它类型：记录一次后跳过，不发布。

## 四、使用步骤

1. 按「二、构建方式」编译，按「三、部署与配置」放置 `.so` 并配置话题映射。
2. 打开 **icaos_tool**，选择「**离线一键启动**」，加载含 `MsgImageDataList` 的测试数据包（RTFBAG 格式，如 `JPEG_2026-05-27-20-16-19_0.bag`）离线回放。
3. 查看发布话题（`rostopic list` 或 icaos_tool 话题视图）：
   ```
   <图像话题>/<frameID>/compressed        # frameID 为空时用索引，如 compressed_image_list/0/compressed
   ```
4. 可视化显示：在 **rviz** 中新增 Image 显示，选择对应 `.../compressed` 话题，即可看到图像。
5. 结束：关闭 icaos_tool / 停止回放，清理无需再运行的插件部署与配置（如需下线可移出 `.so` 并移除话题映射行）。

## 五、常见问题

| 问题 | 原因 / 处理 |
|------|-------------|
| 话题名订阅不到 | 话题为 `图像话题/frameID/compressed`（frameID 空用索引） |
| 图像不显示 | ① 无订阅者的话题会跳过解码/编码（`sub_map`），先加订阅者再回放；② H265 首帧需等 IDR 关键帧，解码前几帧等待属正常 |
| 图像帧率低 | 确认部署的是线程池并行版本（提交 `c19160f1` 之后）；第一版（`83b0f84e`）H265 串行处理会严重降帧 |
| 编译报错找不到库 | 检查 `libde265-dev`、`libturbojpeg`、FFmpeg 是否安装；Ubuntu 18.04 FFmpeg<4.0 需 `avcodec_register_all`（代码已兼容），20.04 ≥4.0 无需 |
| 只处理 JPEG/H265 | 插件只支持 imageType 50/53，其它格式（H264=52、裸格式 0-19 等）会被跳过 |
