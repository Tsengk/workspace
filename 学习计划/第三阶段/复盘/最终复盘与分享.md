### 2. 掌握的能力清单

**语言与框架**：C++、Python3、JavaScript、Vue3、Electron。

**工具软件**：GSDS、ZMQ_TOOL、ICAOS_TOOL、测试任务软件、MRCT、ap_tools、auto_calibration。

**工程能力**：
- 插件化开发（CIdpAbstractPlatform、动态符号导出、IOCTL 分发）
- 图像编解码链路（libde265→I420、FFmpeg→BGR24、TurboJPEG→JPEG）
- ROS（消息/话题发布/订阅者管理/rosbag）
- 性能优化（串行 → 线程池并行、按数据单元分任务、无锁槽位、超时兜底）
- CMake 双平台构建（Ubuntu 18.04/20.04）与部署

**流程规范能力**：
- 任务确认 → 拆解 → 开发 → 自测 → 留痕 → 同步 全流程闭环
- 问题升级 / 根因可自证（代码 diff + 日志 + 对照证据链）/ 最小修复 / 闭环留痕
- 每项任务有验收材料、进度可追溯（任务定义 ↔ 提交号 ↔ 验证结果）

**工具与习惯**：git 提交留痕、调试排障（日志定位）、大模型辅助编程（会用但知边界、逐行理解后再用）。

### 3. 存在的问题与不足

1. **性能风险未前置**：第二阶段 H265 串行帧率问题靠自测兜底才发现，未在任务定义阶段预判性能边界。
2. **工程规范欠账**：`build_2004/` 构建产物混入 git 提交，缺少 `.gitignore` 与构建产物管理。
3. **测试覆盖不全**：H265 帧率复测、x86_1804 平台验证、4K 性能等仍为欠账项。
4. **复用代码理解不深**：部分模块（如 `H26XDecoder`）从既有插件「清洗复制」，内部实现消化不足，初期排障依赖较少。
5. **大模型辅助边界**：初期偶有过度依赖 AI 生成代码，后续改为逐行理解后再使用。

### 4. 后续提升方向

1. 补齐遗留欠账：H265 帧率复测、x86_1804 平台验证、全库排查 `getLidarInstall()` 同类隐患、4K 性能按需实施。
2. 加深源码阅读：坚持每日阅读工具软件模块，理解复用代码内部实现。
3. 需求/任务阶段就评估性能与边界，不等到自测暴露。
4. 工程规范前置：`.gitignore`、双平台验证、构建产物不入库。
5. 保持流程规范习惯，将「留痕/同步/闭环」内化为日常工作方式。
