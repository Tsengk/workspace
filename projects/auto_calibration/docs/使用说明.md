# 自动驾驶标定工具使用说明

## 1. 自动驾驶标定简介

自动驾驶车辆通常装配多种传感器（激光雷达、相机、毫米波雷达、GNSS/IMU 等），每种传感器都有各自的坐标系。为了让不同传感器采集的数据能够在同一个世界中被正确融合，必须先把它们之间的相对位置和姿态精确地测量出来，这个过程就叫做**外参标定**。

本工具提供的能力：

- 主激光雷达对车体（VCS）的 `roll / pitch / z / yaw` 标定
- 辅激光雷达对主激光雷达的 `roll / pitch / z` 与 `x / y / yaw` 标定
- 相机对激光雷达的外参标定（可视化微调）
- 毫米波雷达对激光雷达的标定
- 可视化验证与一键保存结果到 yaml

整体工作流由一个图形化 GUI 驱动，用户不需要逐一编写 launch 文件或节点参数，只需在界面中按步骤操作即可。

## 2. 标定前提准备

### 2.1 传感器数量 / 安装参数

在真正标定之前，车上每个传感器的**粗装参数**必须事先填写到车辆配置文件中（即 `vehicle_sample.yaml` 所示的格式）。工具依赖这份配置来决定播放哪些 topic、启动哪些驱动、以及标定的初值。

安装精度的要求：

- 平移（`x / y / z`）的误差应小于 **10 cm**
- 旋转（`roll / pitch / yaw`）的误差应控制在 **15°** 左右

只要粗装在这个范围内，后续的自动标定算法能够快速收敛；超出这个范围则可能导致算法失败或结果不稳。

车辆参数字段说明（对应 `vehicle` 段）：

| 字段 | 含义 | 单位 |
| ---- | ---- | ---- |
| `id` | 车辆编号 | — |
| `car_length` | 车辆总长 | m |
| `car_width` | 车辆总宽 | m |
| `car_height` | 车辆总高 | m |
| `front_overhang` | 前悬长度（后轴中心到车头距离） | m |
| `wheelbase` | 轴距 | m |
| `rear_overhang` | 后悬长度（后轴中心到车尾距离） | m |
| `z_offset` | 后轴中心到地面的高度 | m |

每个 `lidars` / `cameras` / `radars` 条目的 `t = [x, y, z]` 与 `R = [roll, pitch, yaw]` 即为该传感器在车辆坐标系中的初始安装参数。

### 2.2 相机内参

相机内参由单独的内参标定流程产生，每个相机输出一个独立的 yaml 文件，存放在 `config/intrinsics/` 下，并在车辆配置中通过 `intrinsics_file` 引用：

```yaml
- name: front_103
  topic: /compressed_image_list/1/compressed
  intrinsics_file: intrinsics/front_103.yaml
```

本项目相机以**鱼眼相机（Mei 模型）**为主。Mei 模型在针孔模型的基础上增加了一个镜面反射参数 `xi`，再叠加径向和切向畸变，可以较好地拟合大视场角鱼眼镜头的投影关系：

```
投影过程：
  3D 点 X_c → 单位球面投影 → 偏移 xi → 归一化平面
        → 径向 / 切向畸变 → 像素坐标 u, v
主要参数：
  fx, fy, cx, cy    焦距和主点
  k1, k2, p1, p2    畸变系数
  xi                Mei 模型的镜面偏移
```

内参标定是独立前置步骤，在本工具里**只使用，不再求解**。只要内参文件就绪即可进入外参流程。

### 2.3 车辆坐标系

车辆坐标系（VCS）的定义：

- **原点**：后轴中心在地面上的投影
- **X 轴**：指向车辆前方
- **Y 轴**：指向车辆左侧
- **Z 轴**：指向上方（右手系，前 - 左 - 上）

所有外参的 `t / R` 描述的都是**传感器坐标系相对 VCS 的位姿**。`z_offset` 表示后轴中心（VCS 原点的"空中位置"）到地面的垂直距离，后面主激光 RP 标定中的 `-z_offset` 概念即来源于此。


### 2.4 离线驱动与 topic 配置

实车录制的激光雷达 / 毫米波雷达数据通常是原始的 **packets**（UDP 包级数据），不能直接喂给标定算法，需要通过对应型号的**离线驱动**解码成点云 / 目标话题。

车辆配置中每个 LiDAR 条目都包含两个 topic：

```yaml
- name: front_main_lidar
  packets_topic: /front_main_lidar_packets                      # 原始 packets
  topic: /driver/lidar/cloud//front_main/offline                # 驱动解码出来的点云
  launch_file: sensor_driver/tanway_focus_t_offline/launch/offline_main.launch
```

- `packets_topic` 必须与数据包中录制的实际 topic 名一致
- `topic` 是驱动发布的解码后话题，GUI 会订阅这个话题显示点云
- `launch_file` 指向对应型号雷达的离线驱动 launch

更换不同型号的雷达时，只要替换 `launch_file` 即可；新雷达型号接入时，需要先为它准备对应的离线驱动 launch。

## 3. 软件界面介绍

### 3.1 主界面

![主界面](pic/主界面介绍.png)

主界面由以下几部分组成：

1. **菜单栏**：文件、工具、帮助等入口；导入 / 另存车辆参数也在此处。
2. **Tab 页区**：每个标定任务一个独立的 Tab，按标准流程从左到右排列。
3. **可视化区域**：内嵌 RViz，用于显示点云、图像、目标框等。
4. **操作区 / 状态区**：按钮（播放数据包、启动节点、开启选点、触发标定、保存等）和进度 / 日志输出。

Tab 可通过 `config/tabs_config.yaml` 开关显示，按需隐藏不用的 Tab：

```yaml
tabs:
  - name: lidar_rp          # 主雷达 RP
  - name: lidar_yaw         # 主雷达 yaw
  - name: secondary_rp      # 辅雷达 RP
  - name: lidar_lidar       # 辅雷达 x / y / yaw
  - name: image_lidar       # 相机-LiDAR
  - name: radar_lidar       # 毫米波-LiDAR
```

### 3.2 导入车辆配置

![导入车辆参数](pic/导入车辆参数.png)

标定开始前，第一步统一为**导入车辆配置文件**（`vehicle_sample.yaml` 或自己车辆的同结构 yaml）。GUI 会据此：

- 列出可用的 LiDAR / Camera / Radar 列表
- 自动填入各传感器的外参初值
- 为即将启动的标定节点注入正确的 topic 和 frame id

> 注意：每次启动 GUI 都需要先导入车辆配置，否则启动节点时参数会缺失。

### 3.3 数据包转换

- 1.根据平台选择： 
source env_x86_1804.sh 或者 source env_x86_2004.sh
- BD: 离线转包执行命令
bash merge_bags.sh /mnt/shared/0418/gxs/left_front.avosbag /mnt/shared/0418/ros/


### 3.4 推荐标定流程

标定之间存在依赖关系，需要**从主雷达往外辐射**进行：

```
主激光雷达 RPZ  →  主激光雷达 yaw  →  辅激光雷达 RPZ  →  辅激光雷达 x/y/yaw  →  相机标定  →  毫米波标定
```

后面的标定会直接使用前面标定出的结果，因此**顺序不可颠倒**。

## 4. 激光雷达标定

### 4.1 主激光雷达标定

主激光雷达作为整车坐标系的基准，约定 `x / y` 不参与标定（直接使用车辆配置中的安装量）。需要求解的是 `roll`、`pitch`、`z` 以及 `yaw`。

#### 4.1.1 主激光雷达 roll / pitch / z 标定

**环境要求**：

- 选择尽量平整的场地，自流平地面最佳
- 周围空旷，无明显遮挡物
- 车辆正常停放、减震稳定后采集数据

**操作步骤**：

1. 在菜单栏导入车辆配置文件。
2. 进入「LiDAR RP 标定」Tab。
3. 播放数据包 → 选择主激光雷达 → 叠加显示原始点云 → 开启可视化，确认点云正常。

   ![RP 标定可视化](pic/rp标定.png)

4. 启动节点 → 开启选点模式 → 在车辆前、后、左、右四个方向的地面上各选取若干点。

   ![RP 选点](pic/rp标定1.png)

5. 触发标定，等待结果收敛后保存到 yaml。

   ![RP 保存](pic/rp标定2.png)

**标定验证**：在 RViz 中查看点云，分别读取车辆前 / 后 / 左 / 右四个方向的地面高度。理论上这几处高度与 `-z_offset` 的偏差应在 **±10 cm** 以内，即认为合格。

![RP 验证](pic/rp标定验证.png)

#### 4.1.2 主激光雷达 yaw 标定

**环境要求**：

- 在车辆**正前方**一条直线（沿 X 轴方向）上摆放 **5 ～ 6 个锥形桶**
- 锥桶摆放的直线精度直接决定标定精度，建议拉线辅助定位

**操作步骤**：

1. 播放数据包 → 选择主激光雷达 → 叠加显示原始点云 → 开启可视化。

   ![yaw 标定](pic/yaw标定.png)

2. 启动节点 → 开启选点模式 → 依次选中每个锥桶上的点。

   ![yaw 选点](pic/yaw标定1.png)

3. 触发标定 → 保存结果到 yaml。

   ![yaw 保存](pic/yaw标定2.png)

**标定验证**：在 RViz 中将网格范围扩大，观察锥桶连线是否落在 X 轴（0 点所在的纵向直线）上，应基本贴合。

![yaw 验证](pic/yaw标定验证.png)

### 4.2 辅激光雷达标定

辅激光雷达以标定完的主雷达为参照，分两步完成：先解决 `roll / pitch / z`（保证共面），再解决 `x / y / yaw`（保证共形）。

#### 4.2.1 辅激光雷达 RP 标定

**环境要求**：尽量平地、自流平最佳、周边空旷。

**操作步骤**：

1. 进入「辅雷达 RP 标定」Tab。
2. 播放数据包 → 选择主雷达 → 选择辅雷达 → 同时叠加主雷达和辅雷达点云 → 开启可视化。

   ![f_rp 标定](pic/f_rp标定.png)

3. 启动节点 → 开启选点模式 → 在**主雷达与辅雷达共视区域**中选取地面点。

   ![f_rp 选点 1](pic/f_rp标定1.png)

4. 点击「确认主雷达」 → 在**辅雷达全范围**内选择地面点。

   ![f_rp 选点 2](pic/f_rp标定2.png)

5. 触发标定 → 保存结果到 yaml。

   ![f_rp 保存](pic/f_rp标定3.png)

**标定验证**：在 RViz 中同时显示两个雷达点云，两者的地面应基本**共面**，无明显阶梯或夹角。

![f_rp 验证](pic/f_rp标定验证.png)

#### 4.2.2 辅激光雷达 x / y / yaw 标定

**环境要求**：在主 / 辅雷达的共视区域内**不规则**摆放多个锥形桶（不规则以避免自由度退化）。

**操作步骤**：

1. 进入「LiDAR-LiDAR 联合标定」Tab。
2. 播放数据包 → 选择主雷达 / 辅雷达 → 叠加显示两路点云 → 开启可视化。

   ![f_yaw 可视化](pic/f_yaw.png)

3. 启动节点 → 开启选点模式 → 选取**主雷达**上的锥桶点。

   ![f_yaw 主雷达选点](pic/f_yaw1.png)

4. 点击「确认主雷达」 → 选取**辅雷达**上的锥桶点。

   ![f_yaw 辅雷达选点](pic/f_yaw2.png)

5. 触发标定 → 保存结果到 yaml。

   ![f_yaw 保存](pic/f_yaw3.png)

**标定验证**：在 RViz 中对比两路点云，锥桶与杆状目标应**完全重合**，无平移错位或旋转错位。

![f_yaw 验证](pic/f_yaw_验证.png)

## 5. 相机-雷达联合标定

**环境要求**：让 1 ～ 2 名工作人员站在对应相机前方 3 ～ 10 m 处作为参考目标，保证相机和雷达都能清晰看到。

**操作步骤**：

1. 进入「相机-LiDAR 标定」Tab。前置条件：对应的 LiDAR 已经完成标定。
2. 播放数据包 → 选择参与标定的激光雷达 → 选择目标相机 → 启动节点 → 开启可视化，可看到点云投影到图像上的效果（颜色条表示深度）。

   ![image 投影](pic/image.png)

3. 通过界面上的滑条微调相机的 `roll / pitch / yaw`（以及必要时的 `x / y / z`），使**点云中的人体轮廓与图像中的人体轮廓严格重合**。

   ![image 对齐](pic/image1.png)

4. 点击保存，外参将写入 `config/process/image_lidar_<camera>.yaml`。

> 说明：相机的外参初值来自车辆配置中 `cameras[*].extrinsics`，因此即便手动调整也不会偏得太远；如果初值明显不对，先回到车辆参数把粗装量改准再进入本 Tab。

## 6. 整体精度介绍

完成全部标定后，整车各传感器之间应满足以下经验指标：

| 项目 | 指标 | 检查方式 |
| ---- | ---- | -------- |
| 主雷达地面高度 | `-z_offset ± 10 cm` | RViz 读取四向地面点 Z |
| 主雷达 yaw | 锥桶连线落在 X 轴上 | 扩大网格观察 |
| 辅雷达 RP | 主辅雷达地面共面 | 双雷达叠加点云 |
| 辅雷达 xy/yaw | 锥桶 / 长杆双雷达重合 | 双雷达叠加点云 |
| 相机-雷达 | 人体 / 标志物轮廓对齐 | 点云投影叠加图像 |

以上指标同时满足时，可认为整车标定在可用范围内；若某一项不达标，应回到对应 Tab 重新采集数据或调整外参初值再次标定，不要跳过前置步骤直接进行后续环节。

## 附录 A：标定结果文件

每个 Tab 的标定结果都会写入 `config/process/` 目录，按「标定类型 + 传感器名」命名，例如：

```
lidar_rp_front_main_lidar.yaml         主雷达 RP
lidar_yaw_front_main_lidar.yaml        主雷达 yaw
secondary_rp_front_lidar.yaml          辅雷达 front_lidar 的 RP
lidar_lidar_front_lidar.yaml           辅雷达 front_lidar 的 x/y/yaw
image_lidar_front_103.yaml             front_103 相机-LiDAR
```

这些文件就是下游模块可直接加载的最终外参，也可用于后续迭代标定时作为初值回填到车辆配置文件中。
