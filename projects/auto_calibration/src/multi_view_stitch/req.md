# 多相机边缘对齐与拼接功能需求文档

## 1. 功能名称

基于指定深度的主相机-左右相机边缘对齐与拼接功能

## 2. 功能目标

输入主相机图像、左相机图像、右相机图像，以及三路相机对应的相机模型参数，基于指定对齐深度 `z=n`，计算主相机左右边缘在该深度下对应的世界坐标位置，再投影到左右相机图像中，完成左右图像与主相机图像的裁剪对齐，并最终拼接成一张总图。

该功能用于多相机横向视场拼接场景，目标是在指定深度平面附近获得视觉边界一致的拼接结果。

## 3. 输入

输入包括：

- 主相机图像
- 左相机图像
- 右相机图像
- 主相机 `Mei` 模型参数
- 左相机 `Mei` 模型参数
- 右相机 `Mei` 模型参数
- 对齐深度参数 `align_depth_z`

## 4. 核心定义

### 4.1 对齐深度定义

`align_depth_z` 明确表示：

- 主相机坐标系下的 Z 值
- 单位与相机外参单位保持一致，通常为米
- 必须满足 `align_depth_z > 0`

该值用于主相机图像边缘像素点的 2D->3D 反投影。

### 4.2 边缘中心点定义

主相机左边缘中心点：

- `p_main_left = (0, H_main / 2.0)`

主相机右边缘中心点：

- `p_main_right = (W_main - 1, H_main / 2.0)`

其中：

- `W_main` 为主相机图像宽度
- `H_main` 为主相机图像高度

### 4.3 输出结果定义

输出结果不是独立裁剪图集合，而是：

- 一张最终拼接总图

拼接顺序为：

- 左相机裁剪结果 + 主相机结果 + 右相机裁剪结果

## 5. 参数配置要求

### 5.1 参数名称

建议参数名：

- `~align_depth_z`

### 5.2 配置方式

要求支持以下两种方式：

- 在 launch 文件中通过 `rosparam` 配置默认值
- 在节点运行过程中通过 `rosparam set` 动态修改参数值

### 5.3 动态生效要求

要求动态生效，即：

- 修改 `align_depth_z` 后无需重启节点
- 新参数应在后续处理流程中立即生效

建议实现方式：

- 每帧处理前读取一次参数
- 或在固定周期内刷新参数缓存

## 6. 处理流程

### 6.1 左侧对齐流程

1. 读取主相机图像左边缘中心点 `p_main_left`
2. 在 `camera_z = align_depth_z` 条件下，将 `p_main_left` 反投影为世界坐标点 `P_left_world`
3. 将 `P_left_world` 投影到左相机图像，得到像素点 `p_left_img = (u_left, v_left)`
4. 基于 `p_left_img` 计算左相机有效裁剪区域
5. 将左相机裁剪结果与主相机图像进行严格垂直对齐
6. 参与最终总图拼接

### 6.2 右侧对齐流程

1. 读取主相机图像右边缘中心点 `p_main_right`
2. 在 `camera_z = align_depth_z` 条件下，将 `p_main_right` 反投影为世界坐标点 `P_right_world`
3. 将 `P_right_world` 投影到右相机图像，得到像素点 `p_right_img = (u_right, v_right)`
4. 基于 `p_right_img` 计算右相机有效裁剪区域
5. 将右相机裁剪结果与主相机图像进行严格垂直对齐
6. 参与最终总图拼接

## 7. 接口要求

### 7.1 主相机 2D 到世界 3D

主相机需提供以下接口：

```cpp
bool projectCamera2dToWorld3d(const cv::Point2d& point_2d,
                              const double camera_z,
                              Eigen::Vector3d& point_world) const;
```

语义要求：

- `camera_z` 表示主相机坐标系下的 Z 值
- 输入 `point_2d` 和 `camera_z` 后，输出对应的世界坐标点 `point_world`

### 7.2 世界 3D 到左右相机 2D

左右相机需提供以下接口：

```cpp
bool projectWorld3dTo2d(const Eigen::Vector3d& point_world,
                        cv::Point2d& point_2d) const;
```

语义要求：

- 输入世界坐标点
- 输出该点在目标相机图像中的像素位置

## 8. 裁剪与对齐规则

### 8.1 左相机裁剪规则

以主相机左边缘中心点在左相机中的投影位置 `p_left_img = (u_left, v_left)`` 为基准：

- 左相机保留区域为其与主相机重叠区域之外的有效图像部分
- 第一版建议裁剪边界按列处理，即保留左相机中 `x < u_left` 的区域
- 若 `u_left` 超出左相机图像范围，则判定当前帧左侧对齐失败

### 8.2 右相机裁剪规则

以主相机右边缘中心点在右相机中的投影位置 `p_right_img = (u_right, v_right)` 为基准：

- 右相机保留区域为其与主相机重叠区域之外的有效图像部分
- 第一版建议裁剪边界按列处理，即保留右相机中 `x > u_right` 的区域
- 若 `u_right` 超出右相机图像范围，则判定当前帧右侧对齐失败

### 8.3 垂直方向对齐要求

垂直方向要求严格对齐。

具体要求：

- 左相机、主相机、右相机在参与拼接前必须满足统一的垂直参考系
- 左侧拼接时应基于 `v_left` 与主相机中心参考位置进行垂直对齐
- 右侧拼接时应基于 `v_right` 与主相机中心参考位置进行垂直对齐
- 若严格对齐后没有有效重叠高度，判定当前帧对齐失败

第一版实现建议：

- 通过裁剪公共有效高度实现严格垂直对齐
- 不允许仅忽略 `v_left` 或 `v_right` 而直接拼接

## 9. 拼接规则

最终输出为一张总图，拼接顺序固定为：

- 左裁剪图
- 主相机图
- 右裁剪图

拼接要求：

- 三部分图像在拼接前应具有一致的有效高度
- 高度不一致时，应先完成垂直裁剪对齐，再进行水平拼接
- 若任一部分为空或无有效区域，则当前帧拼接失败

建议输出：

- `stitched_image`

## 10. 失败处理策略

对齐失败时，输出空图。

明确要求：

- 不保留上一帧结果
- 不降级输出原图
- 不输出局部拼接结果
- 当前帧直接输出空图

以下任一情况应判定为失败：

- `align_depth_z <= 0`
- 主相机左边缘点反投影失败
- 主相机右边缘点反投影失败
- 左相机投影失败
- 右相机投影失败
- 投影点不在目标图像有效范围内
- 左相机裁剪宽度小于等于 0
- 右相机裁剪宽度小于等于 0
- 垂直严格对齐后有效高度小于等于 0
- 总图拼接结果为空

## 11. 日志与调试要求

建议输出以下调试信息：

- 当前 `align_depth_z`
- 主相机左边缘中心点像素坐标
- 主相机右边缘中心点像素坐标
- 左侧世界坐标点 `P_left_world`
- 右侧世界坐标点 `P_right_world`
- 左相机投影点 `p_left_img`
- 右相机投影点 `p_right_img`
- 左相机裁剪区域
- 右相机裁剪区域
- 垂直对齐后的公共有效高度范围
- 总图最终尺寸
- 失败原因

## 12. 验收标准

验收通过需满足以下条件：

- 可在 launch 文件中配置 `align_depth_z`
- 可在运行时通过 `rosparam set` 修改 `align_depth_z` 并生效
- 能正确计算主相机左右边缘中心像素在 `camera_z = align_depth_z` 下对应的世界坐标
- 能正确计算该世界点在左相机和右相机中的投影位置
- 能根据投影结果得到左右裁剪边界
- 能基于投影得到严格垂直对齐后的有效拼接区域
- 能输出最终拼接总图
- 参数变化后，左右边界和拼接结果随之变化
- 对齐失败时输出空图
- 整个流程失败时节点不崩溃，并能打印明确失败日志

## 13. 非目标说明

当前版本不包含以下能力：

- 基于特征点或光流的自适应拼接优化
- 融合缝平滑、亮度均衡、羽化处理
- 多层金字塔融合
- 基于地面以外目标的语义对齐

当前版本只解决：

- 基于指定主相机深度的左右边缘几何对齐
- 基于该几何关系的裁剪与严格垂直对齐
- 基于对齐结果的总图拼接
